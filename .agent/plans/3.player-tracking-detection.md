# Phase 3: Player Tracking & Detection System

**Goal**: Integrate Reka.ai Vision API to detect players in sports videos and store tracking data

**Priority**: 🔴 Critical - Core feature for the platform
**Complexity**: 🔴 Complex
**Timeline**: Day 8-10 (2-3 days)

---

## Overview

Build a complete player detection and tracking system that:
1. Sends videos to Reka.ai for object detection
2. Processes bounding box data for each player
3. Stores tracking data in the database
4. Provides manual correction UI for AI mistakes
5. Links detections to player profiles

---

## Sub-Tasks

### 3.1: Reka.ai Vision API Integration ✅ Simple
**Time**: 4 hours

1. Create Edge Function `detect-players`
2. Implement Reka Vision API client
3. Handle video URL submission
4. Process API response
5. Error handling & retries

**API Endpoint**: `/v1/qa/chat` (for object detection queries)

**Example Request**:
```typescript
{
  video_url: "https://storage.url/video.mp4",
  question: "Detect all players in this soccer game. For each player, provide their position as bounding boxes for every frame where they appear. Include jersey numbers if visible."
}
```

**Edge Function**: `supabase/functions/detect-players/index.ts`

---

### 3.2: Bounding Box Data Processing ⚠️ Medium
**Time**: 6 hours

1. Parse Reka API response
2. Extract frame-by-frame coordinates
3. Normalize bounding box format
4. Handle multiple players per frame
5. Store in `video_tracks` table

**Data Format**:
```typescript
{
  frame: 0,
  timestamp: 0.0,
  x: 100,        // top-left x
  y: 200,        // top-left y
  width: 50,     // box width
  height: 120,   // box height
  confidence: 0.95
}
```

---

### 3.3: Player Identification System ⚠️ Medium
**Time**: 8 hours

1. Jersey number OCR (optional via Reka)
2. Player position clustering
3. Auto-assign player IDs based on consistency
4. Link to `players` table
5. Handle player substitutions

**Challenge**: Same jersey number can appear multiple times (teams, substitutions)

**Solution**:
- Track by spatial position + jersey number
- Allow manual reassignment in UI

## Database Queries

### Create Detection Job
```sql
INSERT INTO jobs (user_id, video_id, job_type, status)
VALUES (auth.uid(), $1, 'player_detection', 'queued')
RETURNING id;
```

### Store Tracking Data
```sql
INSERT INTO video_tracks (video_id, player_id, detection_method, frame_data)
VALUES ($1, $2, 'ai', $3::jsonb);
```

### Load Tracking Data for Video
```sql
SELECT
  vt.*,
  p.name as player_name,
  p.number as player_number
FROM video_tracks vt
LEFT JOIN players p ON p.id = vt.player_id
WHERE vt.video_id = $1;
```

import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'

serve(async (req) => {
  const { video_id } = await req.json()

  // 1. Get video URL from storage

    .from('videos')
    .select('storage_path')
    .eq('id', video_id)

## Known Challenges & Solutions

### Challenge 1: Reka API Rate Limits
**Solution**: Queue system with exponential backoff

### Challenge 2: Video Duration Limits
**Solution**: Split long videos into segments (< 2 hours each)

### Challenge 3: Multiple Players with Same Number
**Solution**: Spatial tracking + manual reassignment

### Challenge 4: Player Occlusion
**Solution**: Interpolate between visible frames

### Challenge 5: Low Confidence Detections
**Solution**: Flag for manual review, auto-filter < 70% confidence
